## Implemented

- Your events: GET /me/events?section=upcoming|past&offset=0 lists hosted or joined events independently of geography, 50 per page with next_offset. Upcoming scheduled/future ascending; Past cancelled/completed/elapsed descending. Native Your events tab replaces its fixture preview with loading/error/retry/refresh/load-more sections and shared event detail. Refresh on tab entry, app foreground and mutations. PUT /events/{id}/cancellation verifies demo host, locks the participation event row, allows upcoming scheduled events, and changes to existing cancelled status. Idempotent for already cancelled events; preserves roster and timestamps via existing trigger. Host confirmation in details, loading/tap protection and reconciliation; no notifications yet. No migrations.

- Joining/leaving: PUT/DELETE /events/{id}/participation acts as DEMO_USER_ID with no request body. READ COMMITTED transactions lock the event row, then read membership/capacity before writing. New joins require scheduled/future state and a spot. Already joined/absent returns 204; hosts cannot leave (409). Non-host leaves are allowed regardless of status/time. GET detail includes viewer ID/is_host/is_participant. UI shows Join/Leave/Full/Closed/Hosting, guards double taps, reconciles detail and map after every mutation attempt and handles conflicts/network uncertainty. No schema changes. Seed now includes a fifth joinable cricket event hosted by Demo Sara (11 memberships total) for default Demo Ali to try.

- Event creation: POST /events validates a single JSON object (16 KiB), trimmed 1–200 character title, enum type, future RFC3339 start, positive int32 capacity and place UUID. Server selects scheduled status and configured DEMO_USER_ID (defaults to Demo Ali seed ID). Atomic sqlc CTE inserts event and host membership; response 201 with ID/Location. Missing place is 404, missing demo user/status is 503. No schema changes. Place sheet opens CreateEventForm with local date/time inputs, type/title/capacity, in-flight tap guard, error handling and timeout. Successful creation refreshes viewport without recentring, selects All types and confirms host membership.

- Event browsing: GET /events requires bbox and optionally filters type; returns scheduled future events in start-time/ID order, at most 1000, exact per-place counts and truncated flag. GET /events/{id} includes host, place, status, roster and capacity counts for any event status. Map fetches places/events together, cancels superseded requests, filters All/Football/Cricket, displays event counts on individual markers, place event lists and a separate detail modal with loading/error/retry. Cluster counts explicitly label places. Creation and participation are connected mutation endpoints.

- Migration 000007 renames pins/pin_members to events/event_participants, updates messages.event_id, and introduces event_type/statusable_type enums and shared status rows. Events require host/place/status/title/starts_at/positive capacity including host. Legacy locations become places; legacy expired pins become completed events. Timestamp triggers survive renames; status gets the same trigger. CreateEvent sqlc query inserts host membership atomically. Optional seeds/demo.sql adds six demo users, five events (including open/full/cancelled/completed), eleven memberships; repeated runs preserve counts. Applied locally. Event read endpoints and frontend browsing are described above.

- Migration 000006 simplifies existing users to id (UUID default), required nonblank display_name, created_at and updated_at. Removes email, campus_id and verified_at; no area link. Legacy rows retain IDs and get placeholder name User. Local users table was empty. sqlc user model regenerated. No profile API, frontend, sign-in, sessions or tokens added.

- Go API connected to PostgreSQL/PostGIS, with health, area detail and viewport-place endpoints defined in `openapi.yaml`. pgx/sqlc queries keep geographic filtering in SQL. No sessions or authentication; creation and participation use the configured demo identity.
- Embedded forward-only migration runner with advisory locking, version/checksum ledger and modified-file rejection. Existing initial migration is unchanged. Migration 000002 adds areas/places and database-owned timestamps across application tables and ledger; 000003 seeds LUMS and six sports places from OpenStreetMap, with source links and ODbL attribution. Migration 000004 explicitly declares the legacy timestamp columns for sqlc model generation without changing applied migrations. Migration 000005 converts areas.type and places.type to PostgreSQL area_type/place_type enums while preserving existing data; sqlc generates typed Go enums. Fixed-value fields must use database enums going forward.
- Native MapLibre/OpenFreeMap map replaces the SVG illustration in the map tab. Campus outline, clustered place markers, optional selected-place outline/details, pan/zoom, campus recentre, and loading/empty/error/retry states. Initial campus/API/style are configurable.
