# Campus Pickup: shared context


## Goal and starting scope

Help students at LUMS organise pickup football and tape-ball cricket games, then expand outwards. Start without sign-in or campus verification, with a basic profile and the slim pickup flow in `plan.md`. Sign-in will come later; guest sessions and ownership tokens are deferred.

For each feature, discuss schema with the user, then frontend mechanics, then implement. Work on `main`, uncommitted and unpushed.

## Agreed map direction

Use a real geographic map with MapLibre and OpenFreeMap tiles. This supersedes the immediate illustrated-v6 fidelity milestone. Preserve Floodlight colors/type and keep sample-data previews distinct from connected features. Full prototype coverage remains in `feature-inventory.md`; fidelity references remain in `v6-fidelity-plan.md`.

Explore opens on Lahore and moves through City -> District -> Place cards over a MapLibre map. District and place selections frame the map; a Map button enables free pan/zoom. The hierarchy API supplies districts, places, spots and upcoming events. Empty/loading/error/retry states are required.

## Stack and data rules

- Go HTTP API, pgx/sqlc, PostgreSQL/PostGIS. Existing `net/http` routing is retained; gorilla/websocket supplies realtime transport and PostgreSQL notifications supply fanout. Redis and FCM remain deferred.
- Expo SDK 57, React Native, TypeScript, native MapLibre. OpenFreeMap serves background tiles directly; our API serves our places.
- `openapi.yaml` defines the HTTP contract.
- Numbered forward-only migrations run once, with checksums and applied-version tracking. Never modify applied files.
- Every application table has database-owned `created_at` and `updated_at`. Inserts set both; updates preserve creation time and refresh update time. PostGIS extension metadata is excluded.
- `users`: UUID (generated by default), required nonblank `display_name`, automatic timestamps and optional paired event_goal_target/event_goal_period (positive target, weekly/monthly PostgreSQL enum). No email, campus/area link, or verification fields. Basic profile uses GET/PATCH /me and the You tab; sign-in remains deferred.
- `areas`: City -> District navigation, stable slug/order, optional parent and boundary.
- `places`: terminal destinations inside districts, with stable slug/order, required WGS84 point and optional boundary. `place_spots` holds optional grounds/courts/rooms inside a place.

- `status`: shared UUID/name/unique slug definitions with `statusable_type` enum (event). No statusable_id. Events reference status.id. Initial rows: scheduled, cancelled, completed.
- `events`: UUID, host, place, optional spot, status, required title, user-entered trimmed 1-50 character type, starts_at and positive capacity including host.
- `event_participants`: composite event/user primary key and automatic timestamps. CreateEvent SQL adds host membership atomically.

## Current state

The API connects to PostGIS and serves health, hierarchy Explore, event, chat, realtime and profile/activity endpoints. Native MapLibre loads OpenFreeMap Liberty tiles behind the Explore cards. Initial data is not campus-verified. App tabs are Explore, Your events and You; the old viewport Map screen and its three orphaned backend endpoints are removed. Event creation is connected from a selected place: POST /events uses the configured demo user, sets Scheduled status and atomically joins the host. Joining/leaving is connected in event details using the demo user. Event-row locks serialize capacity checks and roster changes; hosts cannot leave. Your events lists hosted/joined events in paginated Upcoming/Past sections. Host cancellation uses the existing cancelled status, keeps the roster and shares the participation lock. Participant chat is connected through paginated HTTP history, shared WebSocket subscriptions and UUID retry; cancelled/completed history is read-only. Basic profile viewing/name editing is connected. Auth and push remain deferred. Migrations 000009 and 000014 remove the unused legacy reporting/moderation tables. Internal activity reports are implemented; personal analytics are implemented in the You tab.

## Realtime (2026-10-15)

The frozen schema is implemented in migration 000010: polymorphic target_type/target_id streams and outbox, plus messages.sequence. No event revision/counter or payload version columns. One frontend connection serves event details and chat, with transactional updates, sequence recovery, bounded queues, reconnect/foreground recovery and long-poll fallback. PostgreSQL notifications provide cross-instance fanout; Redis is not required for this implementation. See realtime.md for the protocol and deployment limits. Demo identity remains server-configured; production authentication is still deferred.
