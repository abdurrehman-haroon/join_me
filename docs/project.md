# Campus Pickup: shared context

## Goal and starting scope

Help students at LUMS organise pickup football and tape-ball cricket games, then expand outwards. Start without sign-in or campus verification, with a basic profile and the slim pickup flow in `plan.md`. Sign-in will come later; guest sessions and ownership tokens are deferred.

For each feature, discuss schema with the user, then frontend mechanics, then implement. Work on `main`, uncommitted and unpushed.

## Agreed map direction

Use a real geographic map with MapLibre and OpenFreeMap tiles. This supersedes the immediate illustrated-v6 fidelity milestone. Preserve Floodlight colors/type and keep sample-data previews distinct from connected features. Full prototype coverage remains in `feature-inventory.md`; fidelity references remain in `v6-fidelity-plan.md`.

The map opens at LUMS, pans/zooms freely, loads viewport places after movement settles, clusters nearby points, opens a place-details sheet and outline on selection, and recentres on the initial campus. Empty/loading/error/retry states are required. Event browsing now connects the map to upcoming events, filters, place lists and event details.

## Stack and data rules

- Go HTTP API, pgx/sqlc, PostgreSQL/PostGIS. Existing `net/http` routing is retained for this small read-only slice; chi/WebSocket, Redis and FCM remain target choices when needed.
- Expo SDK 57, React Native, TypeScript, native MapLibre. OpenFreeMap serves background tiles directly; our API serves our places.
- `openapi.yaml` defines the HTTP contract.
- Numbered forward-only migrations run once, with checksums and applied-version tracking. Never modify applied files.
- Every application table has database-owned `created_at` and `updated_at`. Inserts set both; updates preserve creation time and refresh update time. PostGIS extension metadata is excluded.
- `users`: UUID (generated by default), required nonblank `display_name`, automatic timestamps only. No email, campus/area link, or verification fields. Basic profile uses GET/PATCH /me and the You tab; sign-in remains deferred.
- `areas`: optional parent, name, `type` as the PostgreSQL `area_type` enum (city/district/campus), optional boundary.
- `places`: area, name, `type` as the PostgreSQL `place_type` enum (ground/court/cafe/park), required WGS84 point, optional boundary. Events reference places.

- `status`: shared UUID/name/unique slug definitions with `statusable_type` enum (event). No statusable_id. Events reference status.id. Initial rows: scheduled, cancelled, completed.
- `events`: UUID, host, place, status, required title, event_type enum (football/cricket), starts_at and positive capacity including host.
- `event_participants`: composite event/user primary key and automatic timestamps. CreateEvent SQL adds host membership atomically.

## Current state

The API connects to PostGIS and serves health, area details, and bounded viewport places. New migrations add geography and timestamp management to existing tables, plus community-mapped LUMS data from OpenStreetMap. Native MapLibre loads OpenFreeMap Liberty tiles and displays the campus and sports places. Initial data is not campus-verified. App tabs are Map, Your events and You; Hostel Cup and fixture UI are removed; event browsing is connected through read-only endpoints and map filters/place sheets/details. Event creation is connected from a selected place: POST /events uses the configured demo user, sets Scheduled status and atomically joins the host. No new schema changes. Joining/leaving is connected in event details using the demo user. Event-row locks serialize capacity checks and roster changes; hosts cannot leave. Your events lists hosted/joined events in paginated Upcoming/Past sections. Host cancellation uses the existing cancelled status, keeps the roster and shares the participation lock. Participant chat is connected through paginated HTTP history, foreground polling and UUID retry; cancelled/completed history is read-only. Basic profile viewing/name editing is connected. Auth and push remain deferred. Reporting is deferred; migration 000009 removes the unused reports table and moderation_log.report_id.
